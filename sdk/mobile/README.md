# MAX Identity Mobile SDK

MAX Identity SDKs provide the native building blocks for signing Android and iOS applications into a MAX Account.

They use **OAuth 2.0 Authorization Code + S256 PKCE**. Android and iOS applications are public OAuth clients: **never ship a MAX client secret inside a mobile app**.

## 1. Register the application

In MAX Developers, create an application with the correct platform type.

### Android

Provide:

- Package name
- SHA-256 signing certificate fingerprint(s)
- Redirect URI, for example `com.example.app://oauth/callback`

### iOS

Provide:

- Bundle ID
- Redirect URI, for example `myapp://oauth/callback`

Use the same `client_id` generated by MAX Developers in the application.

## 2. Android

The Android SDK is in `sdk/android`.

```kotlin
val maxAuth = MaxAuth(
    clientId = "YOUR_CLIENT_ID",
    redirectUri = "com.example.app://oauth/callback"
)

val request = maxAuth.createAuthorizationRequest(
    scopes = listOf("openid", "profile", "email", "offline_access")
)

// Open request.authorizationUrl in an Android Custom Tab or browser.
// Keep request.codeVerifier and request.state until the callback arrives.
```

When the application receives its deep-link callback:

```kotlin
val code = maxAuth.authorizationCode(callbackUri, request.state)
val tokens = maxAuth.exchangeCode(code, request.codeVerifier)
maxAuth.saveTokenSet(context, tokens)
```

The SDK provides:

- PKCE verifier/challenge generation
- OAuth state generation and validation
- Authorization-code exchange
- Refresh-token rotation
- Token revocation
- `/userinfo` access
- Android Keystore-backed encrypted token storage

Network calls are synchronous in the current Android core API, so call `exchangeCode`, `refresh`, `revoke`, and `userInfo` from a background coroutine/thread rather than the Android main thread.

## 3. iOS

The Swift Package is in `sdk/ios` and supports iOS 15+.

```swift
let maxAuth = MaxAuth(
    clientID: "YOUR_CLIENT_ID",
    redirectURI: "myapp://oauth/callback"
)

let request = maxAuth.createAuthorizationRequest(
    scopes: ["openid", "profile", "email", "offline_access"]
)

UIApplication.shared.open(request.authorizationURL)
```

When the app receives the callback URL:

```swift
let code = try maxAuth.authorizationCode(
    from: callbackURL,
    state: request.state
)

let tokens = try await maxAuth.exchangeCode(
    code: code,
    codeVerifier: request.codeVerifier
)

try maxAuth.saveTokenSet(tokens)
```

The SDK provides:

- PKCE verifier/challenge generation
- OAuth state generation and validation
- Authorization-code exchange
- Refresh-token rotation
- Token revocation
- `/userinfo` access
- iOS Keychain-backed token storage

## 4. Complete authentication flow

```text
Mobile app
   │
   │ create PKCE request
   ▼
MAX Auth authorization endpoint
   │
   │ user signs into MAX Account
   ▼
MAX Auth
   │
   │ redirect with authorization code + state
   ▼
Mobile app callback
   │
   │ code + PKCE verifier
   ▼
MAX Auth token endpoint
   │
   │ access token + refresh token
   ▼
Secure platform storage
   │
   ├── Android Keystore
   └── iOS Keychain
```

The mobile application never receives or stores a client secret.

## 5. Token usage

Use the access token as a Bearer token when calling MAX Auth protected endpoints:

```http
Authorization: Bearer ACCESS_TOKEN
```

The SDK's `userInfo` helper calls:

`https://auth.max-ai.name.ng/api/v1/oauth/userinfo`

Refresh tokens are rotated by MAX Auth. Whenever `refresh()` returns a new token set, replace the stored token set with the new one.

## 6. Redirect handling

The SDK validates the callback against the registered redirect URI and the generated OAuth state.

Your Android/iOS application still needs to register the custom URL scheme with the operating system so the callback can reopen the application.

For production applications, prefer an app-owned redirect scheme or platform-supported universal/app link configuration where appropriate.

## 7. Security rules

- Never embed a client secret in Android or iOS code.
- Never log authorization codes, access tokens, refresh tokens, or PKCE verifiers.
- Always use S256 PKCE.
- Always validate `state`.
- Store tokens only in Android Keystore-backed storage or iOS Keychain-backed storage.
- Request only the scopes the application actually needs.
- Use HTTPS for all MAX Auth network traffic.
